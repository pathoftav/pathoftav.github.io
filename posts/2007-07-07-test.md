## 3. Sizing

`w` is a **fixed size**, matching how `h` behaves. `mw` is a **cap**.

`w=20` — one fifth of the column.

![stellar]({site_root}/static/media/test/stellar.png?w=20)

`w=80` — four fifths.

![stellar]({site_root}/static/media/test/stellar.png?w=80)

`mw=20` on a float — caps at 20% instead of the default 45%, so there
should be a long run of text beside it.

![stellar]({site_root}/static/media/test/stellar.png?mw=20#left-inline)
This text wraps beside a float capped much narrower than usual, so there
should be a wide run of words to its right before the line breaks.

<div class="clear"></div>

`w=80&mw=60` — both. Width asks for 80%, the cap holds it at 60%.

![stellar]({site_root}/static/media/test/stellar.png?w=80&mw=60)

`h=200` — pixel height. `h` stays pixels because a percentage height
resolves against a containing block whose height is `auto`.

![stellar]({site_root}/static/media/test/stellar.png?h=200)

`w=40&h=200` — both axes pinned; expect distortion, since nothing
preserves the aspect ratio here.

![stellar]({site_root}/static/media/test/stellar.png?w=40&h=200)

## 3b. Stretching — the reason `w` is a mandate

Needs an asset smaller than its slot. Make one:

```sh
sips -Z 120 static/media/test/stellar.png --out static/media/stellar_small.png
```

No `w` at all — the image should render at its natural 120px and stay
sharp. This is the default.

![small]({site_root}/static/media/stellar_small.png)

`w=40` — the same 120px image stretched to 40% of the column (~270px).
Expect it visibly soft. That softness is the point: `w` obeys you.

![small]({site_root}/static/media/stellar_small.png?w=40)

`mw=40` — a cap, so the small image is left alone at 120px. Compare
directly against the one above.

![small]({site_root}/static/media/stellar_small.png?mw=40)

`w=40` with a caption. The `<figure>` should be 270px wide AND the image
should fill it — if the box is wide but the image stays 120px, the
`width: 100%` on the inner element is missing from your CSS.

![small]({site_root}/static/media/stellar_small.png?w=40 "Stretched and captioned")

No `w`, with a caption. The figure should hug the 120px image instead of
sprawling to the column width. This is the `fit-content` case.

![small]({site_root}/static/media/stellar_small.png "Should hug the image")

Small image floated with no `w` — the float should be 120px wide.

![small]({site_root}/static/media/stellar_small.png#left-inline)
The text beside a naturally-small float should start immediately to its
right, with the float taking only the width the image actually needs.

## 3c. Video pre-load sizing

A `<video>` has no intrinsic size until metadata loads, so it reports the
CSS default 300x150. With a fixed `w` this does not matter — the width is
stated outright. With only `mw`, or with neither, the element renders at
300px and then jumps.

**To observe:** DevTools, Network tab, throttle to "Slow 3G", tick
"Disable cache", hard-reload and watch these.

`mw=50` only — expect a jump on a slow connection.

![waterfall]({site_root}/static/media/aerials-system-of-a-down/waterfall.webm?loop=1&mw=50)

`w=50` — pinned from first paint, no jump.

![waterfall]({site_root}/static/media/aerials-system-of-a-down/waterfall.webm?loop=1&w=50)

`mw=50&ar=16x9` — a cap, but the aspect ratio reserves the box, so this
should also hold still. `ar` is the fix when you want a cap rather than a
fixed width.

![waterfall]({site_root}/static/media/aerials-system-of-a-down/waterfall.webm?loop=1&mw=50&ar=16x9)

`ar=1x1` — deliberately wrong aspect for this clip; should letterbox or
crop rather than distort.

![waterfall]({site_root}/static/media/aerials-system-of-a-down/waterfall.webm?loop=1&ar=1x1&w=30)

Floated video with only `mw`, the worst case — the jump also reflows the
wrapping text.

![waterfall]({site_root}/static/media/aerials-system-of-a-down/waterfall.webm?loop=1&mw=40#left-inline)
Watch this paragraph on a throttled reload. If the float starts at 300px
and then widens, every line here re-wraps.
